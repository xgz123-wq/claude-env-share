防护五层

电脑上有两条路：代理和宽带。宽带一直在，所以要补这五块。点开看细节。

三扇门：Claude Code 和插件 43865，专用 Chrome 43866，Desktop 43867

规则排最前：Claude 的域名和 IP 一律进 ACCOUNT-US

门牌锁死：系统策略把 Desktop 固定在 43867

问路只问自己人：Claude 的 8 个后缀单独加密解析，也走出口

WebRTC：专用 Chrome 的启动参数堵住

侧门焊死：IPv6 在网卡、Clash、DNS 覆写三处都关

工牌保安（WFP）：认程序，名单内的 Claude 程序只许连本机

大门黑名单（防火墙）：认地址，谁直连 Anthropic 网段都拦

名单外：Code 标签页、Cowork 虚拟机、GitHub MCP、curl、git、node 没有保安，直连时只有 Anthropic 网段被拦

注意：节点不通时 Clash 还开着，请求只是发不出去，不算漏

三端更新：一个入口，先给新版加防护，再切换

官方域名复核：每周或更新后跑一次

英文入口启动 Desktop；专用 Chrome 带语言参数；时区卫士能一键修；定位手动关，没有脚本查

更新为什么不能省

加了 downloads.claude.ai 也不能省，因为这是两件事。

域名规则管：走哪个出口下载地址早被 claude.ai 后缀覆盖，实测进 ACCOUNT-US。它不在 Anthropic 网段，防火墙管不到，全靠这条规则
更新流程管：保安还认得人保安按文件路径认程序，路径一变就认不出新版
程序更新后路径更新后要同步防护吗
Desktop 主程序变要，先加防护再切换
VS Code 插件变要，重新登记
Claude Code不变不用，按官方签名放行；更新本身也走三端更新
Code 标签页变Desktop 自己更新，路径随版本变，没登记；跑总检时查一次当下连接

出问题

不确定就把报错发给 AI。常见的这几种：

看到什么怎么办
「Claude Desktop / Code 直连防护」红灯，启动器拒绝启动多半刚更新过（版本不符、插件路径变了、文件基线不一致），走三端更新
「Clash 规则同步」黄灯运行中还有旧规则：在 Clash Verge 里点重载。现场 Script.js 不一致：先让 AI 复制到现场，再点重载。都不影响现在的分流
「Claude 规则实际命中」红灯规则没生效或被抢走，发给 AI
「Claude 程序实际连接」黄灯或红灯有程序直连外网或不在名单，发给 AI
「Claude Code 43865」这类入口项红灯这扇门到不了 claude.ai，多半是节点不通；换节点后重新体检
「Rule / TUN / Claude 规则」红灯看失败项：切成了全局模式、TUN 关了、ACCOUNT-US 没选节点或不通、新规则没重载。恢复后点重载；换订阅后要重选节点
Desktop 一直转圈看 43867 还在不在，把总检结果发给 AI
Claude Code 连不上，Desktop 正常看总检「Claude Code 代理设置」
国内能上，代理全挂可能是 MTU，发给 AI 说「查 MTU」
出口在意外国家，或 IP 被标为机房节点问题，换节点后重新体检

细节

部署和深究时才用，日常不用看。

Clash 设置页
  • 模式选规则；TUN 开；系统代理关
  • IPv6 关；DNS 覆写开，里面的 IPv6 也关
  • 混合端口设为 43865
  • 这几项都在设置页改，不写进脚本
全局脚本做了什么

文件是 Clash/Clash全局账号通道.js，装在 Clash Verge 的「全局扩展脚本」。它对所有订阅生效，规则插在最前（总检核对顺序），换订阅也不用改。

  • 新建 ACCOUNT-US 组，包含订阅全部节点，你手选一个
  • 规则最前面插 Claude 规则，清掉订阅自带的 Claude 规则
  • 开两扇门：43866、43867
  • Claude 的 8 个后缀单独加密解析，TUN 接管所有 53 端口的 DNS 查询
  • 过滤订阅注入的邮件端口直连规则
  • geo 数据库每天更新，缺库整份配置会加载失败
两个组选不选同一个节点

ACCOUNT-US 选好后不要乱换。节点挂了不会自动切换，就断在那里。

选法结果
不同出口 IP普通国外流量不和 Claude 共用 IP；要有两个出口不同的节点，主线、备线出口相同的换了也分不开
同一个出口 IP全机国外流量和 Claude 同一个 IP，容易用杂；不影响防护

两种选法总检都不会误报。

Claude Code 的 settings.json

只改 env，不要整份覆盖。

键值
HTTP_PROXY、HTTPS_PROXY、ALL_PROXYhttp://127.0.0.1:43865，不能填 43866
NO_PROXYlocalhost,127.0.0.1,*.local，不能写网段
DISABLE_AUTOUPDATER1，统一走三端更新
ANTHROPIC_BASE_URL、ANTHROPIC_API_URL不要设，否则请求发去第三方；总检会报红灯
专用 Chrome

用 工具/创建账号浏览器.ps1 -Alias 别名 生成，每个账号一个。不要用 Chrome 的「添加用户」。新建和登错账号见排障与变更。

  • 独立数据目录：--user-data-dir，在 %LOCALAPPDATA%\ClaudeAccountBrowsers\
  • 走 43866：--proxy-server
  • 自己不查 DNS：--host-resolver-rules
  • 英文：--lang、--accept-lang
  • 堵 WebRTC：--force-webrtc-ip-handling-policy

这些参数只在桌面快捷方式里，从别处打开的 Chrome 一个都没有。确认办法：地址栏输入 chrome://version。

Claude Desktop 的策略和防护
  • 门牌锁死：系统策略 egressProxyUrl 指向 43867
  • 关自动更新：disableAutoUpdates，必须和上一条在同一层
  • 工牌保安：4 个程序路径（Desktop 1、Claude Code 2、插件 1），各两条规则，共 8 条
  • 别用：Claude自动更新管理.ps1 -Action Enable 会连带删掉代理策略
DNS 和 IPv6

Claude 的 8 个后缀用专用解析器，经 ACCOUNT-US 查；普通域名问海外 DoH，国内域名问国内 DNS；国内网站解析到国内地址是正常的。详见排障与变更「DNS 与 IPv6」。

IPv6 关哪怎么关
网卡网卡属性取消勾选 IPv6；新增网卡要重做
Clash设置页 IPv6 开关
DNS 覆写DNS 覆写页的 IPv6 开关
会让配置直接崩的坑
  • 规则指向不存在的组，或写了库里没有的 geosite 分类：整份配置校验失败，这次重载不生效
  • 把全机 DNS 改成国外加密 DNS：国内应用断网
  • 用旧文件覆盖现场 Script.js：新规则被冲掉；总检会提示不一致
  • 把 client-fingerprint 写成 fingerprint：节点连不上
杀毒和检测站
  • 杀毒白名单：给 Clash Verge 加白名单；代理程序常被误删，门一没 Claude 全断
  • 一个浏览器只登一个账号
  • 换订阅：导入后在 ACCOUNT-US 手选节点，再体检；全局脚本不用动
  • 检测站：页面上几个「出口」IP 不一样不一定有问题（原因没查实）；Claude 的出口跨国或露出本地 IP 才算红灯

只讲网络配置，目的是消除误路由和信息泄漏，不涉及也不建议伪造身份、绕过封禁或规避官方核验。账号资格、付款方式和实际所在地必须符合 Anthropic 当前条款与支持地区。
