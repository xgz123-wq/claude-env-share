# Claude 账号浏览器

> 整理日期：2026-09-23
> 一句话：每个 Claude 账号一个专用 Chrome，数据目录各自独立，网络都走 `43866 → ACCOUNT-US`。

## 怎么用

- **打开**：只从桌面上该账号的专用 Chrome 快捷方式进；开始菜单、任务栏里的 Chrome 不带防护参数。
- **一个浏览器只登一个账号**：Cookie、网站存储、登录数据按目录隔开。
- **分别验收**：每个专用 Chrome 各自看检测站，一个通过不代表另一个也通过。
- **隔离的是数据，不是出口**：所有专用 Chrome 共用同一个出口。

## 新增一个账号浏览器

1. 告诉 AI 想要的别名，例如「账号2」。
2. AI 先查同名快捷方式或目录是否已存在，存在就先检查，不直接覆盖。
3. AI 用 Skill 工具 `scripts/apply/创建账号浏览器.ps1 -Alias <别名>` 生成独立目录和快捷方式，再同步拓扑记录和入口检查。
4. 你自己打开新浏览器，登录账号，看一遍检测站。

- **不要用 Chrome 自带的「添加用户」**：它在同一个数据目录里多开 Profile，达不到隔离。

## 登错账号后清理网站数据

适用：在某个专用 Chrome 里误登了别的谷歌账号或别的 Claude 账号。对 AI 说「<浏览器名> 里 claude.ai 登错账号了，帮我清 Claude 的网站数据」。

1. 在该浏览器的谷歌账号页面退出多出来的那个谷歌账号。
2. 地址栏打开 `chrome://settings/content/all`，右上角分别搜 `claude`、`anthropic`，把 claude.ai、claude.com、anthropic.com 每行点垃圾桶删除。
3. 打开 claude.ai 确认是未登录状态，点「Continue with Google」，账号框里只应出现这个浏览器自己的谷歌账号；出现两个就先停。
4. AI 只读核对：该浏览器 `UserData\Default\IndexedDB` 下已没有 `https_claude.ai_0.indexeddb.leveldb`。

- **由用户在浏览器里删，AI 不直接删文件**：Cookie 和 Local Storage 是所有网站共用的数据库，按文件删清不干净，浏览器开着时还可能写坏数据。
- **检测站某项「获取失败」先查插件**：uBlock Origin Lite 等拦截插件会拦 `cloudflare.com/cdn-cgi/trace`，在该站把拦截设为 `no filtering`。

## 给 AI 的边界

| 要求 | 说明 |
|---|---|
| 先读现场 | 先看 [Claude 配置总览](../README.md)，再核对实际快捷方式、目录和网络配置 |
| 不碰账号数据 | 不读、不复制 Cookie、密码、令牌、登录数据库，也不从别的账号目录拷数据 |
| 不启动浏览器 | 维护时默认不启动；真实浏览器验收单独安排 |
| 不覆盖 Clash | 不用旧文档或 Skill 脚本覆盖 Clash 现场生效脚本 |
| 如实汇报 | 只建了文件不等于已登录或验收通过；汇报时分开写已验证和未验证 |
