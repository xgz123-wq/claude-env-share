# Claude 环境排障与变更（给 AI）

> 2026-11-14 由 Skill `claude-safe-network`（含 3 份参考）、`DNS分层说明.md`、`Anthropic网段直连阻断.md`、`账号浏览器.md` 合并而成，同一事实只在这里写。
> 命令路径相对项目根，一律 `pwsh -NoProfile -File`；端口 43865 / 43866 / 43867 是默认值，本机以[部署清单](../README.md#部署清单)为准。更新三端走[更新维护说明](../Desktop防护/更新维护说明.md)。

## 1. 边界与红线

- **AI 只做核对、审查和报告**：不重启、不热重载 Clash，不启动或退出 Claude 和浏览器，不改 `ACCOUNT-US` 手选节点、DNS、IPv6、HKLM 策略，除非用户当次明确要求。
- **不外泄**：订阅 token、节点 uuid、REALITY public-key、真实出口 IP 不进回复、文档、提交；不读、不打印 `~/.claude/.credentials.json`、`~/.claude/settings.json`、Clash `profiles.yaml` 的订阅详情。
- **不主动测 IP**：没有用户明确要求不跑检测站、不解读结果；不承诺「规避检测」，只做「出口干净、不泄漏、不旁路」。
- **先怀疑取证方法**：一份不完整的枚举不能推翻已验证通过的结论。

## 3. 架构要点

```
Claude Code / VS Code 插件 ─HTTP 43865─┐  （按规则：Claude 域名 → ACCOUNT-US）
专用 Chrome ───────────── SOCKS 43866 ─┼─► Clash Verge Rev（mihomo，TUN + 规则模式）─► ACCOUNT-US（手选节点，组里没有 DIRECT）
Claude Desktop ─────────── HTTP 43867 ─┘  （43866、43867 的 listener 写死 ACCOUNT-US）
其余程序经 TUN：国内名单直连，其余全部 ACCOUNT-US（MATCH 兜底）
兜底：WFP 拦 4 个 Claude 程序直连；防火墙拦任何程序直连 Anthropic 两个网段
```

### 全局扩展脚本 `Script.js` 做的事

现场在 `%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\profiles\Script.js`，唯一来源是 `Clash/Clash全局账号通道.js`。它是 `profiles.yaml` 顶层的全局条目，对所有订阅生效，换订阅不用改。

| 做什么 | 要点 |
|---|---|
| 重建 `ACCOUNT-US` 组 | `select`、`include-all-proxies: true`、排除 Direct/Reject：自动吃下新订阅节点，节点挂了就断 |
| `GLOBAL` 组只含 `ACCOUNT-US` | 误切全局模式也不直连（2026-11-10 事故后加） |
| Claude 后缀的 DNS policy | Claude 后缀用 `1.1.1.1` / `8.8.8.8` DoH 并显式经 `ACCOUNT-US`；不覆盖 `nameserver`、`direct-nameserver`、`fallback`。规则模式下通用 DNS 本来也走 `ACCOUNT-US`，它保的是直连模式（2026-11-14 核对后保留） |
| TUN 防旁路 | `strict-route: true`、`dns-hijack: [any:53, tcp://any:53]`；静态 `config.yaml` 写 `false` 正常，以运行时为准 |
| 两个 listener | `account-us-socks`（43866）和 `claude-desktop-http`（43867），都写死 `proxy: ACCOUNT-US`，切全局、直连都不变 |
| 规则清理与置顶 | 按 `claudeIdentity` 清掉订阅自带的 Claude 规则和无条件邮件直连，置顶 Claude 规则和 DoH 直连 |
| 统一海外出口（2026-11-14） | 订阅规则里除 DIRECT/REJECT 外的目标一律改指 `ACCOUNT-US`；`GEOSITE,cn` 前插 `mirrorakam` 直连（B 站视频）和 `GEOSITE,geolocation-!cn,ACCOUNT-US`；`GEOIP,CN` 带 `no-resolve`；末尾 `MATCH,ACCOUNT-US` |
| `geox-url.asn` | 指向 MetaCubeX 的 ASN 库；`IP-ASN` 规则缺库会让整份配置加载失败 |

- **规则明细**：只在 JS 的「规则清单」一段维护，全表看[入口页规则表](架构讲解.html#rules)；`工具/读Claude规则.ps1` 按变量名逐行解析，不要改写法。
- **遥测**：sentry、statsig、datadog 等第三方服务整类不入 Claude 规则（别的软件也在用），只有官方点名的 `http-intake.logs.us5.datadoghq.com` 按完整域名入组；不入组也不直连，由海外分类或 `MATCH` 送进 `ACCOUNT-US`。

### DNS 与 IPv6

- **普通 DNS**：Clash Verge 的 DNS 覆写 `dns_config.yaml` 优先于订阅，`nameserver` 只放海外 DoH（`https://8.8.8.8/dns-query`、`https://1.1.1.1/dns-query`），不放 `doh.pub`、`dns.alidns.com` 这类国内 DNS（11-07 泄露根因）；运行配置开了 `respect-rules`，DNS 连接跟着规则走 `ACCOUNT-US`。
- **国内域名 DNS**：靠订阅带来的 `geosite:cn,private` 策略问国内 DNS；换订阅后确认运行配置 `clash-verge.yaml` 里还有这条。国内网站解析到国内地址不是泄漏；不在国内域名库里的小众国内网站会问海外 DNS，可能变慢。
- **浏览器安全 DNS 保持关闭**：浏览器自带 DoH 走 443 不受 53 劫持；`cloudflare-dns.com`、`dns.google` 规则强制直连，否则落兜底进美国线路，国内域名被解析成海外 IP（09-28 Edge）。普通 Chrome 不加专用 Chrome 的 `--host-resolver-rules`。
- **IPv6 三层关闭**：网卡（WLAN 等取消勾选 TCP/IPv6，`Mihomo` 虚拟网卡保持开启；命令 `Disable-NetAdapterBinding -Name 'WLAN' -ComponentID ms_tcpip6`，新网卡要重做）、Clash 全局 `ipv6: false`、DNS 覆写 `ipv6: false`；本机无公网 IPv6 地址和默认路由，卫士 S4 查。

## 5. 故障决策树

按顺序查：

| 步 | 查什么 | 怎么查 | 期望 / 处理 |
|---|---|---|---|
| -1 | **国内网站正常、走代理的全挂**：MTU 黑洞 | `ping -f -l 1472 8.8.8.8`，超时再试 `-l 1464` | 1472 超时、1464 通 = 链路丢大包：Clash TUN「最大传输单元」设 `1380`，上网网卡 `netsh interface ipv4 set subinterface "WLAN" mtu=1400 store=persistent`（管理员），两处都要设；换网卡、Clash 重置、网络重置后复查；根治在路由器 WAN 1492 + MSS 钳制。节点测速用 `generate_204` 在黑洞下会假通过。不换订阅不换节点 |
| 0 | 根本没起来 | `Get-NetTCPConnection -State Listen` 看 43865/43866/43867 | 三行，进程 `verge-mihomo`；缺了看 Clash Verge「全局扩展脚本」能否预览 |
| 1 | 组没选中 | Clash Verge「代理」页 | `ACCOUNT-US` 有选中节点；新订阅不会自动选中，用户手动选 |
| 2 | 规则在不在 | 总检的规则项；`查域名走哪条规则.ps1 <域名>` 真发请求看命中 | 第 1 条是 `IN-NAME,account-us-socks`；Claude 规则全部指向 `ACCOUNT-US`、排在通用规则前；规则页只显示后缀，搜不到子域名是正常的 |
| 3 | 出口一致 | `curl.exe --max-time 10 -s --proxy http://127.0.0.1:43865 https://claude.ai/cdn-cgi/trace`，43866 用 `socks5h://`，43867 用 `http://` | 三个 `ip=` 相同；不同就先别用 Claude。不用第三方测 IP 站判断 43865 |
| 4 | DNS 旁路 | `clash-verge.yaml` 的 `strict-route`、`dns-hijack`；连接表搜 `cloudflare-dns.com` 等 DoH 端点 | 探针 DNS 返回 `198.18.0.0/16`（fake-IP）；浏览器自带 DoH 关掉 |
| 5 | Desktop 专项 | HKLM 策略、configLibrary、`应用直连防护状态.json` 与 `应用过滤目标.json` | 见第 3 节；英文启动器 `Assert-GuardEvidence` 不通过会 `[BLOCK]` |
| 6 | 升级后 | Desktop 或插件换了版本目录 | WFP 按完整路径匹配，路径一变规则挂空且不报错，必须走三端更新迁移 |

## 6. 不是问题、误判坑、环境坑

| 现象或做法 | 实际情况 |
|---|---|

| 检测站反复访问出 Cloudflare 挑战页 | 站点按出口 IP 限流，不是本机问题 |

## 7. 变更 SOP

> 总原则：能只改开关就不改文件；能只改全局脚本就不碰订阅。任何变更收尾都做第 7.5 节。

### 7.1 换订阅或换节点后

脚本和规则一行不用改。步骤：① 用户在 Clash 给 `ACCOUNT-US` 选节点；② 跑一键总检 0 FAIL、三入口出口一致；③ 卫士体检 P3–P5 全绿，命中机房或黑名单就换节点；④ 用户在专用 Chrome 看检测站，页面 IP 与总检一致。

**IP 信誉站判读**（只在用户要求时用）：`ip.net.coffee/claude/` Trust Score ≥ 80、家庭住宅；`ping0.cc` 风控值 < 20%、原生；`ippure.com` 系数 0%；`iprisk.top` 纯净度 ≥ 90、黑名单全清。出现「机房 / 数据中心」或黑名单命中就换节点；`新 IP < 3 月` 这类时间分可以接受。

### 7.2 改端口或改组名（不建议改）

端口源头在 Clash，只在 Clash 一侧改，跑一次一键总检刷新部署清单，脚本和卫士按名字取：

| 位置 | 内容 | 谁改 |
|---|---|---|
| Clash Verge「设置 → 端口设置」 | 混合端口（= 清单 `通用`） | 用户 |
| `Clash/Clash全局账号通道.js` → 现场 `Script.js` | 两个 listener 端口、组名、DNS policy 的 `#ACCOUNT-US` | AI 改，用户重载 |
| `~\.claude\settings.json`、各专用 Chrome 快捷方式、HKLM `egressProxyUrl` 和 configLibrary | 各自端口 | 用户 |
| 部署清单、环境卫士 | 三个端口 | 不手改，总检刷新 |

改组名先 `grep -rn "ACCOUNT-US" docs/配置/Claude环境 --include=*.ps1 --include=*.js` 逐个改；改了 Desktop 端口再确认启动器 `-CheckOnly` 通过。

### 7.3 收到外部域名、网段清单，或域名复核报新域名

| 步 | 做什么 | 谁做 |
|---|---|---|
| 1 | `查域名走哪条规则.ps1` 实测、`检查Claude官方域名.ps1` 查官方，分成已覆盖、该加、不加、说法站不住 | AI |
| 2 | 列给用户确认加哪些；共享第三方域名写进 `检查Claude官方域名.ps1` 的 `$sharedHosts` 并写原因，不绑定 `ACCOUNT-US` | 用户定 |
| 3 | 只改 JS 的规则清单或 `Anthropic网段直连阻断.ps1` 的网段；新 geosite 分类先用内核 `-t` 校验 | AI |
| 4 | 跑 `工具/生成架构讲解.ps1` | AI |
| 5 | 内核校验通过、备份现场后复制到 `Script.js` | AI（用户当次确认） |
| 6 | Clash Verge 里重载；改了网段时以管理员装防火墙规则 | 用户 |
| 7 | 总检、完整性 0 FAIL，再实测新规则命中 | AI |

- **域名复核时机**：后台出口巡检每天自动跑一次，有未归类新域名弹窗；Desktop、CLI、插件更新后，订阅或规则变化后，登录、下载、桥接异常时手动再跑。来源是 [Desktop 网络要求](https://code.claude.com/docs/en/desktop#network-access-requirements)和 [Claude Code 网络要求](https://code.claude.com/docs/en/network-config#network-access-requirements)；`-OfflineDir <目录>` 可离线测试。
- **归类**：被 Claude 后缀或精确域名覆盖的算已覆盖；在 `$sharedHosts` 的算共享（npm、GitHub、Google Storage、`browser-intake-us5-datadoghq.com`、字体与脚本 CDN）；其余是未归类。

**内核校验做法**：python `yaml` 把现场 `clash-verge.yaml` 转 JSON → node 用 `new Function(src+';return main;')()` 调 JS 的 `main` → 转回 yaml → 把 Clash Verge 目录的 `geoip.dat`、`geosite.dat`、`*.mmdb` 复制到同一临时目录 → `"C:\Program Files\Clash Verge\verge-mihomo.exe" -t -d <临时目录> -f config.yaml`。临时目录放 scratchpad，配置里有节点信息，不打印。把已处理过的配置再喂一遍 JS，Datadog 精确域名和两条 DoH 规则会重复，这是旧现象，实际重载用原始订阅不会重复。

### 7.4 回滚

## 8. 专用 Chrome（账号浏览器）

- **一个账号一个专用 Chrome**：数据目录各自独立，出口共用 `43866 → ACCOUNT-US`；隔离的是数据，不是出口。只从桌面快捷方式打开；不要用 Chrome 自带的「添加用户」（同一个数据目录，隔离不了）。
- **新建**：用户给别名 → AI 先查同名快捷方式或目录，存在就先检查不覆盖 → `工具/创建账号浏览器.ps1 -Alias <别名>` → 用户自己打开、登录、看检测站；一键总检自动发现桌面上新增的专用浏览器。
- **登错账号**：用户在该浏览器里退出多出来的谷歌账号 → `chrome://settings/content/all` 搜 `claude`、`anthropic` 逐行删网站数据 → 重新打开 claude.ai，「Continue with Google」里只应出现这个浏览器自己的账号。AI 只读核对 `UserData\Default\IndexedDB` 下已没有 `https_claude.ai_0.indexeddb.leveldb`，不直接删文件（Cookie 是共用数据库，浏览器开着时删会写坏）。
- **AI 边界**：不读、不复制 Cookie、密码、令牌、登录数据库；维护时不启动浏览器；只建了文件不等于已登录或验收通过。
- **检测站某项「获取失败」**：先看 uBlock Origin Lite 等插件是否拦了 `cloudflare.com/cdn-cgi/trace`。
