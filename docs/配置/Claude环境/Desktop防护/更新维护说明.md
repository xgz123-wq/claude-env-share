# Claude 三端更新维护说明（给 AI）

> 更新日期：2026-11-14（并入原 Skill `claude-maintenance`，更新流程只在本页维护）。当前版本与历次证据见 [维护日志](../维护日志.md)；网络排障见[排障与变更](../说明/排障与变更.md)。
> 端口：文中 43865 / 43866 / 43867 是默认值，本机以部署清单为准，见 [README「部署清单」](../README.md#部署清单)。路径相对项目根，脚本一律用 PowerShell 7。

## 边界

- **更新由用户做**：退出全部 Claude 后双击桌面「Claude-三端更新」（= `Desktop防护/更新三端Claude.ps1`）。AI 只做只读扫描、读记录、写文档和报告；不跑 Update、不跑 `一键更新`，不重启或热重载 Clash，不启动或退出 Claude，除非用户当次明确要求。
- **触发**：用户说「Claude 更新」「看看要不要更新」「更新完了」才走本页；「Claude Code Desktop」这类含混称呼不等于三端全更新，确定不了对象时只问这一项。
- **Claude Code 会话里跑不了 Update**：`claude.exe` 在运行会报 `blocked_running`。

## 为什么比「直接更新」多几步

- **直连防护**：4 个 Claude 程序各有按程序路径匹配的 WFP 规则，清单记着 SHA-256 指纹。路径变了（插件、Desktop 换版本目录）规则就挂空，必须迁移；CLI 自更新只变指纹不变路径，规则仍生效，总检、启动器、Verify 按有效的 `Anthropic, PBC` 签名放行。
- **Desktop 禁自动更新**：HKLM 策略关掉了 Desktop 自更新，只能经 43867 下载官方包，先给新版路径加好防护再安装。

脚本部分约 2–5 分钟（Desktop 下载 300 MB 约 3 分钟，安装与核验约 2 分钟；只同步插件约 70 秒）。

## 先分流

| 用户意图或变化 | 做什么 |
|---|---|
| 要不要更新 | 跑 `更新三端Claude.ps1 -Action Check`（只查，约 10 秒，Claude 开着也能跑） |
| 只有 CLI 变了（自动更新或 npm） | 不用同步；Check 确认版本，需要时跑总检看到「按 Anthropic 签名放行」即正常；维护日志写一行 |
| 插件换了版本、Desktop 最新 | 轻量：用户跑三端更新（约 1 分钟，一次 UAC）→ AI 读记录、日志写一行，不跑域名复核、清理清单和分享包同步 |
| Desktop 有新版 | 走下面三步 |
| 用户说「更新完了」 | 直接做第 3 步 |
| 检查防护状态 | `一键更新ClaudeDesktop.ps1 -Action Verify`（要 UAC，先告知用户） |

## 三步：扫描 → 更新 → 收尾

1. **扫描（AI）**：`-Action Check` 输出三端已装 / 最新版本和 4 个程序的指纹状态（`unchanged` / `changed_signed` / `moved` 等）；用户手动更新过任一端，以本次扫描为准。插件和 CLI 落后都不用手动处理，第 2 步脚本自己装（CLI 只用 `registry.npmjs.org`，不用 `npm update -g`；插件只要求先退出 VS Code）。
2. **更新（用户，一次 UAC）**：按屏幕最后几行的 Status 走：

| Status | 含义 | 下一步 |
|---|---|---|
| `blocked_running` | 有 claude 进程在跑 | 退出后重跑 |
| `blocked_locked` | 另一份三端更新正在跑（桌面图标或环境卫士） | 等它结束，不要两边同时点 |
| `blocked_vscode` | 插件落后但 VS Code 开着；没下载、没改文件 | 退出 VS Code 全部窗口后重跑 |
| `up_to_date` | 三端最新，防护不用动 | 不用更新 |
| `passed` | 全部完成，屏幕有前后版本、Verify、总检、各步秒数 | 第 3 步 |
| `failed` | 防护、日志、安装包都保留 | 读记录 `Error`，按下面「失败与同版本」处理；注册前失败用 `-ResumeJournal` 续接；不重跑碰运气 |

   输出互相矛盾（指纹对不上、Desktop 被外部更新、上次中断）就停下按「失败与同版本」处理，不要单独再跑 `应用直连防护管理.ps1 -Action Refresh`。

3. **收尾（AI）**：
   - **读记录**：`%LOCALAPPDATA%\ClaudeNetworkGuard\更新记录-<时间>\记录.json`，字段 `Products`（前后版本）、`CliInstall`、`PluginInstall.Retries`、`Desktop.DownloadSeconds / Reused`、`Maintenance.StepSeconds / Checks / HashCount / FiltersCount / Cleanup`、`After`（含 `PluginProtected`）、`Timing`；没计时的段写「未计时」，不估算。
   - **域名复核**：跑 `Clash/检查Claude官方域名.ps1`，退出码 1 有新域名按[排障与变更 7.3](../说明/排障与变更.md#73-收到外部域名网段清单或域名复核报新域名)处理。
   - **清理**：跑 `清理维护残留.ps1`（默认只列清单），列给用户确认后加 `-Yes`。
   - **文档**：按项目根 `AGENTS.md` 写维护日志、README 当前状态；改了做法同步分享包。凡修复（脚本 bug、流程坑、假警报）当场写进维护日志：问题、根因、修复、验证。

- **完成标准**：三端版本回读等于最新（用户暂缓的一端写进未验证）、签名审核通过、管理员 Verify 4/4 文件 8/8 规则、活动插件路径与清单一致、总检 0 FAIL、维护日志已更新；任一项没满足不能写「全部完成」。汇报时分开写配置检查、管理员实际规则核验、真实应用验收。
- **纪律**：不翻脚本源码找参数（输出已含全部字段）；不为留一份干净记录重跑 UAC；用户已明确要求更新时不重复确认；UAC 是系统授权，不承诺零交互。

## 入口

| 文件 | 用途 |
|---|---|
| `更新三端Claude.ps1` | **唯一入口**，桌面「Claude-三端更新」指向它。不带参数：查三端版本 → CLI 落后自动 `npm install -g`（只用 `registry.npmjs.org`）→ 插件落后用 VS Code 命令行 `code --install-extension anthropic.claude-code@<最新版>` 装（装完核对 `extensions.json` 只登记一条、`pinned=true`、`targetPlatform=win32-x64`，不合格用装之前的备份恢复并报失败；装时每 15 秒上屏已等秒数，下载重试也上屏，次数记在 `记录.json` 的 `PluginInstall.Retries`）→ Desktop 落后从官方入口下载并审核（同版本审核过的包直接复用）→ 登记 4 个目标指纹 → 弹一次 UAC 调 `一键更新` 跑完 → 回读三端版本。`-Action Check` 只查版本和 4 个指纹状态，不下载、不提权、不改文件，Claude 开着也能跑。Status：`blocked_running`（有 claude 进程）、`blocked_vscode`（插件落后但 VS Code 开着；退出 VS Code 后重跑，不强杀）、`plugin_update_needed`（10-24 之前的旧脚本：插件落后要用户在 VS Code 点更新）、`up_to_date`（防护不用动）、`passed`、`failed`、`checked`。每次 Update 在 `%LOCALAPPDATA%\ClaudeNetworkGuard\更新记录-<时间>\` 留 `记录.json`（版本前后、下载秒数、各步秒数、Verify、总检、清理）和全部日志；Check 只留 `检查记录-<时间>.json`。弹 UAC 后管理员进程在隐藏窗口里跑，每步开始、结束写一行 `统一维护\进度.log`，主窗口每秒转印为「UAC 内 开始 / 完成 <步骤>（秒数）」。下载时屏幕每秒刷新已下载 MB 和速度，临时文件名 `Claude-<版本>-下载中.msix`（审核只认 `.msix`）；下载失败整包重下，不做跨次续传；子脚本结果都走文件，不解析屏幕输出 |
| `一键更新ClaudeDesktop.ps1` | 由 `更新三端Claude.ps1` 调用，一般不单独跑：`-Action Verify` 只核验；`-Action Update -PackagePath '<官方包绝对路径>' -ApprovedSHA256 '<审核后指纹>'` 更新 Desktop；再加 `-CliApprovedSHA256 '<h1>','<h2>','<h3>','<h4>'` 在同一次提权里刷新清单中 4 个目标的指纹；只更新 CLI 同路径文件时只传 `-CliApprovedSHA256`；插件换版本目录时加 `-PluginApprovedSHA256 '<新插件审核后指纹>'`，在同一次提权里最先迁移；`-ResultDirectory` 指定结果目录 |
| `更新ClaudeDesktop.ps1` | 底层：官方包审核（`-Action Inspect`，加 `-ResultPath` 把结果另存成文件）、Stage、预保护、Register |
| `应用直连防护管理.ps1` | 管理员 Verify、同路径 Refresh、插件换目录 MigratePlugin、独立阻断探针 |
| `../启动Claude英文浏览器.ps1` | `-CheckOnly` 只检查，不启动 Desktop |

- **授权**：CLI 指纹刷新、Desktop 迁移、管理员 Verify 都在 `一键更新` 的同一个工作进程里，正常只弹一次 UAC。单独以管理员身份运行 `应用直连防护管理.ps1 -Action Refresh` 会多弹一次（09-25 那次共弹 3 次就是这个原因）。
- **清理**：`Update` 全部核验通过后，自动删除 `%ProgramData%\ClaudeNetworkGuard\` 和 `%LOCALAPPDATA%\ClaudeNetworkGuard\Desktop安装包下载\` 里的 `Claude-<版本>.msix`（从 Codex 发起时，还会清理 `Packages\*\LocalCache\Local\ClaudeNetworkGuard\Desktop安装包下载\`），删除清单写进 `结果.json` 的 `Cleanup.Removed`；失败时保留安装包，供 `-ResumeJournal` 续接。
- **保留最新两个版本**：每个目录按版本号保留最高的两个包（刚装的新版和刚被替换的旧版），记进 `Cleanup.Kept`，只删更老的。原因是刚参与安装的包删得很慢（10-14 约 96 秒，10-15 124.9 秒，10-23 删刚被替换的旧版 175.8 秒），放凉后删只要约 1 秒。代价是两个目录各多占约 0.3 GB，直到下次更新。
- **运行中的 Claude**：发现正在运行时停止维护，不强杀用户任务。
- **并行查版本**（10-24）：Desktop 官方入口、npm、VS Code 市场三个远端源各开一个后台线程同时查（`Start-ThreadJob`），本机三项同时在主线程读；报错顺序和串行时一样。实测查版本从约 7 秒降到约 3 秒。
- **单实例锁**（10-24）：Update 持有互斥锁 `Local\ClaudeThreeEndUpdate`，同时再起一份（桌面图标或环境卫士）会直接退出（退出码 1），不建记录目录、不下载；Check 不加锁。
- **给环境卫士的可选参数**（10-24，不传时行为不变）：`-RunDirectory '<目录>'` 指定本次记录目录（Update 用它代替 `更新记录-<时间>`；Check 写成其中的 `检查记录.json`；撞上单实例锁时在里面写 `Status=blocked_locked` 的 `记录.json`）；`-ChangedOnly` 经 `一键更新 -ChangedOnly` 让 UAC 内日常总检只查 Desktop 策略与直连防护（总检 `-Scope Guard`，约 18 秒 → 约 5 秒），Clash、出口、快捷方式、网段阻断不查。
- **Code 标签页不归这里管**：Desktop 自己下载和更新，路径带版本和哈希，WFP 登记不了；边界见[入口页](../说明/架构讲解.html#arch)。

## 官方包审核

- **来源**：官方入口见上面「关键位置」，由 `更新三端Claude.ps1` 执行；不要去 `claude.com/download` 网页上找链接。
- **审核项**：Anthropic 有效签名、包家族、版本、依赖、Manifest 启动与服务声明；包架构必须与已装版本一致；新增可执行文件必须审阅保护范围。
- **安装源**：下载件先放在 `%LOCALAPPDATA%\ClaudeNetworkGuard\Desktop安装包下载\`，`一键更新` 再复制到 `%ProgramData%\ClaudeNetworkGuard\Claude-<版本>.msix` 并复核 SHA-256。
- **安装卷**：Stage 必须显式指定当前安装卷（09-20 未指定卷时报 `0x80070003`）。
- **禁止**：放宽系统权限或修改应用仓库来绕过错误。

## 执行顺序

1. 读实际版本、进程、HKLM 禁更与代理策略；确认旧版规则与指纹通过。
2. 备份将改动的清单、状态、策略、脚本。
3. Stage 新版文件 → 为新版主程序路径加规则并验证 → Register 切换版本。
4. 更新目标清单与状态，管理员 Verify；成功后只清理旧 Desktop 规则，保留 Code 规则。

依据：[微软对 Add、Stage、Register 的说明](https://devblogs.microsoft.com/insidemsix/add-vs-stage-and-register/)。

## 失败与同版本

| 情况 | 处理 |
|---|---|
| Register 前失败 | 修复原因后用原 `-ResumeJournal '<更新过程.json>'` 续接，避免再次 Apply 产生孤立规则 |
| Register 前文件占用 | 退出 Claude 后用 `ForceTargetApplicationShutdown` 清理目标包占用 |
| Register 后失败 | 保持应用关闭，按新版补齐防护、状态、同步与 Verify；不得恢复旧清单冒充已保护 |
| 版本相同 | 只核验并补齐收尾，不重复安装 |
| 装插件等很久或中途关了窗 | 正常约 1 分钟；下载中断时 VS Code 自动从头重下，不续传。这一步还没动防护，关窗只结束脚本，`code` 安装进程可能继续跑完（11-03 实见）。超过 3 分钟想换手动：结束本次 → VS Code 扩展页点更新（也是从头下）→ 退出 VS Code → 重跑三端更新迁移防护，最后这步不能省 |
| 外部更新或中断后指纹对不上 | 先算文件实际哈希，比对文件修改时间与基线准备时间：落盘晚于基线是「更新异步落盘」，不是篡改；签名 Valid（Anthropic, PBC）、版本与包一致后，按清单顺序执行 `应用直连防护管理.ps1 -Action Refresh -ApprovedSHA256 <4 个哈希> -SkipNetworkProbe` 接受（一次 UAC，需退出全部 Claude，失败自动回滚） |
| 想降级 | 配置备份不含旧安装包，不能承诺降级；不得直接跑整体 Rollback |

- **不采用 IFEO 启动锁**：试验中挡得住同名探针，挡不住真实 MSIX 启动，已移除。

## 同步与核验

- **唯一一份**：脚本和状态 json 只在本目录；桌面快捷方式和环境卫士都调这里（2026-10-26 起 Skill 不再保存副本，一键更新也不再同步副本）。
- **策略**：`disableAutoUpdates` 与 `egressProxyUrl=http://127.0.0.1:43867` 必须同在 HKLM 层；不得调用 `Claude自动更新管理.ps1 -Action Enable`（会删掉同层代理策略）。
- **收尾**：一键总检 + 启动器 `-CheckOnly`；结果按上面第 3 步写进维护日志。

## 防护边界

- **匹配方式**：WFP 按完整程序路径阻断非回环出站，本机代理连接放行；SHA-256 只用来发现程序变化。
- **覆盖**：Desktop 主程序 + 两个 CLI npm 程序 + VS Code `anthropic.claude-code` 插件内置程序，共 4 个文件；不保护整个 `Code.exe`，Cowork、虚拟机、SSH 辅助程序、外部浏览器不在内。
- **CLI 同路径变化**（自动更新或 npm 更新）：WFP 规则按路径仍生效；总检、启动器、管理员 Verify 对两个 `Claude Code npm` 目标按有效的 `Anthropic, PBC` 签名放行（Verify 记录 `AcceptedBy=signature`），不用单独弹 UAC。新指纹在下次 Desktop 或插件维护时随 `-CliApprovedSHA256` 登记；签名无效或签名方不对仍 FAIL。Desktop 和插件仍只认登记指纹。
- **其他同路径变化**：审核来源、签名、指纹后，通过 `一键更新 -Action Update -CliApprovedSHA256 <按清单顺序的四个本次审核指纹>` 执行（内部就是 `Refresh -SkipNetworkProbe`）；指纹不能复制历史值。
- **插件路径**：从 `%USERPROFILE%\.vscode\extensions\extensions.json` 读取当前活动 `anthropic.claude-code`，要求唯一、`pinned=true`、`targetPlatform=win32-x64`，且没有 `claudeCode.claudeProcessWrapper`；任一项变化，总检和启动器都阻断通过。
- **路径变化**：Desktop 或插件升级换目录时必须迁移规则，不能只刷新指纹。插件由 `应用直连防护管理.ps1 -Action MigratePlugin` 完成（经一键更新调用）：先退出 VS Code 和全部 `claude.exe`，给新路径加规则并核验、更新清单和状态，最后撤旧规则；任一步失败就撤新规则、恢复清单，旧规则不动。
- **启动器**：只做启动前检查，不持续监视已运行程序。
- **跨机器**：新机器重新识别路径和目标，不能导入本机状态 JSON 充当验收。
